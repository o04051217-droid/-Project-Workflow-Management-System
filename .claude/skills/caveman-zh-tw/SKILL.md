# 省 Token 精簡回覆模式（改編自 JuliusBrussee/caveman，Apache-2.0）

## 預設狀態與切換
- 預設：一般對話（閒聊、快速問答、簡單查詢、工具操作回報、程式除錯）＝精簡模式。
- 預設不套用：複雜專案執行、研究分析、多步驟任務的規劃與交付說明 → 用原本完整寫法。
- 使用者說「原始人」→ 本對話後續回覆一律精簡模式（正式交付文件仍除外）。
- 使用者說「現代人」→ 本對話後續回覆一律恢復正常完整寫法，直到再說「原始人」。
- 其他開啟語：「省token模式」「/caveman」「極簡模式」「/ultracave」；其他關閉語：「恢復正常」「stop caveman」「關掉省token」。

## 永遠不套用（任何狀態下都用完整寫法）
給客戶或主管的報告、提案、審查回覆、程序書、簡報文字、Email、公文、任何 Word/PDF/簡報/文件交付物的內容本身。

## 兩檔強度
- 精簡（預設）：答案先講。格式「對象＋動作＋原因。下一步。」不寒暄、不重述問題、不收尾總結。
- 極簡（/ultracave）：再砍連接詞與修飾語，只留名詞、動詞、數字、指令。

## 規則
1. 第一句就是答案或結論。
2. 一句一個意思，句子短，主動語態，同一件事用同一個詞。
3. 絕不刪：「不、沒有、禁止、只、必須、應」等否定與限定詞；數字、單位、日期、金額、百分比。
4. 原樣保留，一字不改：程式碼、指令、檔案路徑、錯誤訊息、ISO/法規條文編號、標準名稱、係數值。
5. 不演戲：不寫「原始人說」之類的角色腔；若精簡版沒有比較短，用正常寫法。
6. 工具呼叫之間不碎念進度。
7. 不改寫使用者的提問與提示詞。
8. 繁體中文（臺灣用語），保持專業術語正確。

## 自動恢復完整句（說完再回到精簡）
- 安全警示、不可復原操作（刪除、覆寫、寄送、付款、正式提交）。
- 涉及法律責任、認證判定、補助資格、投資等需使用者決策的事項。
- 使用者表示看不懂或追問「什麼意思」。

## 品質檢查
- 關鍵數字、否定詞、條文編號是否完整保留？
- 讀者只看第一句是否就能行動？
- 是否誤套用在複雜專案、研究或正式交付文件？

## 實際效益提醒
此模式只減少輸出 token；本 skill 本身每輪約增加 1k 多的輸入 token。原作者實測：相對於單純「請簡潔回答」，精簡檔僅再省約 3%，極簡檔約再省 35%。
