# 設計美感（改編自 Leonxlnx/taste-skill 與 taste-skill-classics，MIT）

> 原版 v2 需 Node 22+、Chrome 與網路找圖，本環境無法執行其腳本；此為純指引版。
> 與 intellicore-consulting-deck、document-font-layout-rules 衝突時，以該兩者為準。

## 使用時機
HTML 頁面、Claude 成品頁（Design/Dashboard/hand-built）、儀表板、活動海報、教育訓練或提案簡報的版面設計。

## 必要輸入
客戶或主題、讀者（主管／審查委員／學員／一般大眾）、用途、品牌色或範本（若有）。

## 執行步驟
1. 讀需求，列出「只有這個客戶／主題才有」的素材：產品、製程、數據、地點、案例照片。沒有獨特素材就先問或用真實數據撐場，不用通用圖庫感素材。
2. 提出 3 個方向（例：編輯雜誌感、工業技術感、沉穩報告感），選 1 個並說明理由；重要案件讓使用者選。
3. 寫一句設計概念：把客戶素材和方向綁在一起。
4. 依下方規範製作。
5. 檢查：手機 390px、平板 768px、桌機 1280px 三種寬度（可截圖就截圖看）。
6. 找出最嚴重的 3 個問題修正，最多 3 輪。

## 字型（中文環境）
- 內文：Noto Sans TC 或 系統黑體；標題可用 Noto Serif TC 製造對比。英文避免 Inter、Roboto、Open Sans 這類預設字。
- 標題緊行距（約 1.15–1.25），內文行高 1.6–1.8。
- 內文不用純黑 #000，改深炭灰 #1F2328～#2F3437；次要文字 #6B6B6B 左右。
- 字級層級最多 4–5 級，對比要明顯。

## 色彩
- 底色白或暖白（#FFFFFF／#F7F6F3），主色 1 個、強調色最多 1–2 個，用在數據與重點。
- 大面積區塊不用高飽和原色；不用霓虹、紫藍漸層、玻璃擬態。
- 狀態色用低彩度粉色底＋深色字（紅 #FDEBEC/#9F2F2D、藍 #E1F3FE/#1F6C9F、綠 #EDF3EC/#346538、黃 #FBF3DB/#956400）。

## 版面與元件
- 先定留白：區塊間距大，內文寬度限制在約 60–75 個中文字。
- 卡片：1px 淺灰框線（#EAEAEA），圓角 8–12px，內距 24–40px；陰影幾乎不用。
- 表格：一律保留可見格線（使用者偏好），數字靠右、對齊小數點。
- 文字框、卡片大小貼合內容，不留大片空白、不溢出。
- 每頁第一屏要有清楚標題；左右邊距一致；不出現無意義空白帶。
- 儀表板：面板安靜、顏色只花在數據上、數字對齊；手機版導覽收合。

## 禁用的「AI 味」元素
- emoji 當圖示或標題裝飾。
- 假名稱與假字：王小明、ABC 公司、Lorem ipsum；一律用真實或合理情境內容。
- 空洞文案：「賦能」「助力」「打造全方位」「無縫」「引領未來」「一站式」「顛覆」「深度融合」。文案交給 zh-tw-de-ai-polish 再過一次。
- 三欄等寬圖示卡片＋置中標題的萬用落地頁結構。
- 每張卡都放細線圖示、到處都是膠囊按鈕、大陰影。

## 動態（網頁才用）
- 只動 transform 與 opacity；進場淡入位移 12px、約 600ms；列表錯開 80ms。
- 必須尊重 prefers-reduced-motion。
- 正式報告、PDF、列印物不加動態。

## 品質檢查清單
- 是否一眼看得出是這個客戶／主題，而不是任何公司都能套？
- 三種寬度皆無橫向捲動、無文字溢出？
- 表格有格線？字型統一？色彩不超過規定數量？
- 圖片來源可授權且已標示；無真實人物照片濫用。

## 常見錯誤
- 先套模板再塞內容 → 內容薄、版面漂亮但空。先備齊素材再排版。
- 過度留白導致資訊不足 → 審查簡報與儀表板密度可提高。
