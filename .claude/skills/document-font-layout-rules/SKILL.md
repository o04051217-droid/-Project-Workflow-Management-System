# 文件字型與排版規則

使用者要求：未來所有產出資料，字型、字體大小須前後一致，並在交付前確認實際排版結果。

## 第一步：有沒有範本或附檔

- 使用者提供範本、樣板或附檔格式時：先和使用者確認排版（字型、字級、邊界、標題層級、頁首頁尾）後再產出，不自行改動。
- 沒有範本時：依下列類型判斷字型。

## 第二步：依文件類型選字型

| 文件類型 | 字型 |
|---|---|
| 政府公文（函、簽、公告、計畫書回覆等正式送機關文件） | 正式公文字體。預設中文標楷體、英數 Times New Roman；字級依機關格式或文書處理手冊。機關有指定格式時以指定為準，不確定就先問使用者 |
| 一般文件（報告、備忘、說明、清單） | 數字與英文用 Arial，中文與英文用新細明體（PMingLiU） |
| 要求稍有美感、或需展示說明的文件 | 標楷體 |
| 要求極致美感的文件 | hanaMINA（花園明朝） |

分辨不出類型時，先用一句話問使用者，不要猜。

## 第三步：一致性與分頁

- 全文只用該類型指定的字型；標題、內文、表格、註腳各層級的字級固定，不得混用。
- 表格內文字級與內文相同或統一縮小一級，整份一致。
- 用樣式（Style）設定，不逐段手動調整。
- 章節切換時一律強制分頁（每個主章節標題前插入分頁符，或設「段落前分頁」），方便閱讀；封面、目錄、附件也各自獨立成頁。分頁後確認表格不被中間截斷、標題不落在頁尾。
- 段落若被頁面切開（一段文字跨頁斷開），須在該段前插入分頁（或設「段落中不分頁」「與下段同頁」），讓整段移到下一頁完整呈現，不得留下被切開的段落。
- 若字型需要使用者電腦已安裝（例如 hanaMINA），交付時說明；環境缺字型時不得悄悄改用別的字型，要告知使用者並說明替代方案。

## 第四步：交付前檢查排版

- 實際渲染（轉成 PDF 或圖片）並逐頁查看：字型是否套用、有無亂碼或缺字、表格是否跑版或被截斷、段落是否跨頁被切開、分頁位置、頁碼。
- 有問題先修正再交付；無法修正（例如文件工具不支援指定字型、紅字或強制分頁）時，改用 Word（docx）產出，並告知使用者。
- 政府補助申請書與回覆說明如要求頁碼，需加頁碼（頁尾置中，十進位數字）。

## 資料不足時的草稿做法

- 正式回覆不得把答案延後成「送件前確認填列」。使用者要求先模擬推估時，直接寫上推估答案，用紅色字標記，表示後續須修正；紅字不得傷造已完成、已簽約或已取得的事實，只用合理的預估值與計畫陳述。
- 交付時附一份紅字項目清單，說明每項的推估依據與需確認的人。
- 內部備註、待辦、狀態說明不放進正式文件內文；需要時另放內部清單並標明送出前刪除。
- 文件即將送交審查委員或機關時，正文不得出現「新增」「刪除」「本次修訂」「建議」「待確認」等版本對照或內部說明字句；變更說明只在對話中告知使用者。

## 申請書日期

- 政府補助申請書封面的民國日期為「送件日期」，不是草擬日；使用者告知送件日時，封面日期須同步更新（例如 115年10月29日）。
