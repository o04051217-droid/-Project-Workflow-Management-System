# LLM 議會決策（方法論參考 Karpathy llm-council 三階段：獨立意見 → 匿名互評 → 主席裁決）

> 本版為單一模型扮演多位顧問，不是真正的多模型投票。若使用者貼入 ChatGPT、Gemini 等其他 AI 的回答，將其列為額外議員一起進入互評，才算真正跨模型。

## 使用時機
- 適合：有不確定性、做錯代價高的判斷。例：報價要不要降、提案策略選哪個、客戶回函立場、是否接案、投資部位調整、ISO/碳盤查方法學爭議、補助計畫亮點取捨。
- 不適合：有單一正確答案的查詢、單純撰寫或摘要任務。遇到時直接回答，不開議會。
- 觸發語：「開議會」「council this」「議會審一下」「壓力測試」「stress-test」「war room」。

## 必要輸入
1. 決策問題（一句話）。
2. 選項（若有）。
3. 背景、限制、期限、預算；有文件就先讀。
缺少會改變結論的關鍵資訊時，只問 1 個最重要的問題；否則直接開會並註明假設。

## 議員（5 位，視角刻意不重疊）
1. 標準與證據審查官：條文、法規、官方公告、數據來源是否站得住；區分強制要求與建議做法。
2. 業主／決策者視角：對方老闆或審查委員真正在乎什麼，會怎麼解讀。
3. 成本與風險精算師：金錢、時間、人力、機會成本、最壞情境與機率。
4. 落地執行者：實際做得出來嗎？誰做、多久、卡點在哪。
5. 反方代言人：專門找致命漏洞，主張其他人忽略的選項，包括「什麼都不做」。
可依題目替換其中 1～2 位（例：投資題換成「基本面分析師」「籌碼與技術面」），但必須維持反方代言人。

## 執行步驟
### 第一階段：獨立意見
- 每位議員各自作答，彼此不參考。每人：立場（一句）＋3 個理由＋1 個最大擔憂＋信心度（低/中/高）。
- 需要現況資料（法規、價格、公告）時先查證，標示來源；查不到就標「待確認」，不得編造。

### 第二階段：匿名互評
- 把五份意見改標為 A～E（打亂順序，不標身份），每位議員評其他四份：最強論點、最弱論點、遺漏了什麼。
- 排出最具說服力的前兩名。

### 第三階段：主席裁決
主席整合，不得只取多數決，要以證據強弱為準。

## 輸出格式
1. **裁決**：建議做什麼（一句話）＋整體信心度。
2. **共識點**：議員都同意的事。
3. **主要分歧**：誰主張什麼、主席採納哪方及理由。
4. **最大風險與因應**：反方提出且未被駁倒的風險。
5. **改變結論的條件**：出現哪些資訊時應重新評估。
6. **下一步**：1～3 個具體行動。
7. （可收合）五位議員原始意見與互評摘要。
手機閱讀時，1～6 控制在一個畫面內。

## 品質檢查
- 五位意見是否真的不同，而非同一觀點換句話說？
- 反方是否提出實質挑戰？若全員一致，主席須說明為何仍不擔心。
- 數字、條文、公告是否有來源或已標待確認？
- 裁決是否回應使用者原本的問題，而非轉移題目？
- 是否誠實指出使用者可能不想聽的結論，不迎合既有傾向。

## 常見錯誤
- 角色扮演變成表演 → 去除人設口吻，只留論點。
- 主席和稀泥 → 必須做出選擇，並說明代價。
- 把客戶回函、對方說法當成事實 → 審查官與反方須逐點檢驗。
- 涉及法律責任、正式認證、投資下單 → 裁決僅供參考，最終決定交使用者，並註明非法律或投資建議。
