# 繁中文章去 AI 味

## 使用時機
- Claude、ChatGPT 等產出的文章、報告、提案、信件，讀起來「一看就是 AI 寫的」，需要改成自然、具體、符合臺灣用語的顧問文風。
- 文字從 AI 介面複製出來，帶有隱形字元、不一致的標點或 Markdown 殘留。

## 範圍說明
- 目標是文章品質：自然、具體、用語正確。
- 不以「通過 AI 偵測器」為目標，不跑偵測分數迴圈，也不對外宣稱結果「無法被偵測」。
- 交付對象（學校、期刊、部分政府計畫或客戶合約）若規定需揭露 AI 使用，提醒使用者照規定揭露；本技能不用來規避揭露義務。

## 必要輸入
1. 文章（貼上的文字，或 .txt、.md、.docx 檔）。
2. 用途與讀者：政府提案、客戶報告、教育訓練、信件或社群貼文。
3. 改寫強度：輕（只清痕跡與用語）、中（預設）、重（重組段落）。

## 執行步驟

### 第一層：字元與格式清理（用程式處理，不靠眼視）
```python
import re, unicodedata
INVISIBLE = '[\u200b\u200c\u200d\u2060\ufeff\u00ad\u180e\u202a-\u202e\u2066-\u2069\ufe00-\ufe0f]'
def clean(t):
    t = re.sub(INVISIBLE, '', t)
    t = t.replace('\u00a0', ' ').replace('\u3000', ' ')
    t = re.sub(r'[ \t]+\n', '\n', t)
    t = re.sub(r'\n{3,}', '\n\n', t)
    return t
```
- 先列出各類字元的數量，再清除。
- 中文句內標點一律用全形（，。、；：？！），引號用「」『』；英數字保持半形。
- 破折號「——」或「—」過多時，改用逗號、括號或斷句。
- 移除不該出現在最終文稿的 Markdown 符號（**、##、- 開頭的條列），或轉成 Word 的正式標題層級。

### 第二層：用語校正（大陸用語 → 臺灣用語）
常見對照（依語境判斷，不硬替換）：
數據→資料、信息→資訊、質量→品質、項目→專案／計畫、優化→改善／最佳化、視頻→影片、軟件→軟體、網絡→網路、文檔→文件、頭部企業→領導廠商、落地→實際導入、抓手→切入點、打造→建立、資質→資格、審核→審查、培訓→教育訓練、認證審核→驗證稽核。

### 第三層：去除 AI 套路（改寫）
先標出以下特徵，再改寫：
- **套語與空詞**：值得注意的是、總而言之、綜上所述、在…的背景下、隨著…的發展、至關重要、全方位、深入探討、旨在、賦能、助力、不僅…更…、一方面…另一方面…。能刪就刪，不能刪就改成具體內容。
- **三段式排比**：「提升效率、降低成本、強化競爭力」這類湊三項的寫法，只留有證據的項目。
- **每段結尾的總結句**與「希望以上對你有幫助」類收尾：刪除。
- **條列過多**：敘事或論述段落改回段落；粗體只留必要的關鍵字。
- **冒號標題式句子**（「關鍵挑戰：…」）：改成完整句。
- **抽象主詞**：把「本計畫將有助於…」改成「誇廠導入後，備料工時從 4 小時降到 2.5 小時」，用公司、人、設備、數字當主詞。
- **句長過於平均**：長短句交錯，允許偶爾的短句。
- **過度保留語氣**（可能、或許、在一定程度上）：有證據就直說，沒證據就標「待確認」。

文風依用途調整：
- 政府提案／審查回覆：正式、具體、量化，對應審查重點。
- 客戶報告：顧問口吻，先講發現、再講建議。
- 信件／社群：口語、簡短，少用條列。

## 品質檢查（必做）
1. **事實不變**：用程式比對改寫前後的數字、百分比、日期、金額、標準條文編號（如 ISO 14064-1 5.2.3）、專有名詞。清單不一致的項目逐一檢查。
```python
nums = lambda t: sorted(re.findall(r'\d+(?:[.,]\d+)*%?', t))
assert nums(before) == nums(after) or print(set(nums(before)) ^ set(nums(after)))
```
2. **專業術語不被改錯**：標準用語（排放源、組織邊界、功能單位、截斷準則、矯正措施等）維持官方譯名。
3. **沒有新增或刪除主張**。
4. 重新跑一次第一層清理。
5. 對正式文件，另搭配 reader-cold-read 技能做讀者冷讀。

## 輸出規格
- 改寫後的全文（或「原檔名_polished」檔案，原檔保留）。
- 修改摘要：清除的字元數、替換的用語、主要改寫類型（3–5 項）。
- 事實檢查結果與待確認事項。

## 常見錯誤與處理
- **改寫時把數字或條文改掉**：以品質檢查第 1 項的比對為準，還原原值。
- **用語硬替換造成錯誤**：例如「質量」在物理計算中是 mass，不能改成品質；「項目」若指清單中的項目則保留。
- **改得太口語**：依用途決定文風，正式文件不用網路語氣。
- **全部改成段落，反而難讀**：真正列舉型的內容（步驟、檢查表）保留條列。
